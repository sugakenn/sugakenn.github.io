近頃は、Webだけでなく、コード署名やDBMS接続など、プライベートな運用でも証明書の実装が必要なケースが増えてきました。鍵を作ったり証明書を作ったりするのは、ChatGPTの手を借りながらできるのですが、CAの管理となるとまだできていません。

今回は、OpenSSLで動かすCAをちゃんと運用ベースにのせるために、設定等の整理をしたいと思います。


##  x509の署名では、失効リスト(CRL)が作れない

openssl x509はCAの鍵セットを指定して署名する方法で、手軽に実行できます。この時出力されるのは、-CAcreateserialで指定された、連番管理ファイルだけでこれは消えても簡単に復旧させられれますし、再度
オプションを使えばリセットはされます。

このシリアル番号はCA自身が発行した証明書を一意に識別するためのもので、証明書を使うアプリケーションが利用する頻度は少ないので簡易的な運用時にはあまり重要な要素ではありません。

失効リスト(CRL)を運用したい場合は、この番号が重要になってきますが、基本的にx509で署名をした場合は、標準のコマンドだけでは失効リストは作れません(人的な作業をして作成するのは可能です)。

```
openssl x509 \
  -req \
  -in host.csr \
  -CA ca.crt \
  -CAkey ca.key \
  -CAcreateserial \
  -out host.crt \
  -days 365 \
  -sha256 \
  -extfile openssl-v3-sig-ext.cnf \
  -extensions host_cert 
```

```
# openssl-v3-sig-ext.cnf
[ host_cert ]
basicConstraints = critical,CA:false
keyUsage = critical,digitalSignature
extendedKeyUsage = clientAuth
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid,issuer
```

## openssl.cnfを複数もつ運用

本格的にCAを運用するには署名時にopenssl ca コマンドを使います。こちらのコマンドを使うと、発行履歴をファイルへ保存するようになります。

インストール時に、Debianなら`/etc/ssl/openssl.cnf`に設定ファイルが配置され、そこには`CA_Default`というセクションがあり、CA用の設定を記述できます。

また、このセクションに倣って、`CA_ANOTHER`として作成すれば、
```
openssl ca -name CA_ANOTHER 
```
とすることで、複数のCAを使い分けることができます。

この書き方だと、設定の記述が長くなりミスが起きやすいので、ディレクトリ毎にCAを分けそれぞれにopenssl.cnfを持つ運用にした方が管理が楽です。


さらに、ディレクトリ名もCommon Nameに一致させるようにするとより管理が楽になると思います。

コマンド実行時は、-configオプションで設定ファイルを指定できます。


## 中間CAの運用

v3署名で仕様目的を制限すれば、たとえばコード署名用の証明書をWi-Fi接続用に使われるということはありません。なのですべてRoot CAで管理することは可能です。

しかし、CAの秘密鍵が漏洩した際の被害の範囲を制限するために、中間CAを設けてRoot CAの鍵はオフライン保存するなどした上でRoot CAを利用する頻度を減らし、中間CAにはEKU(Extend Key Usage)を指定し、目的にあったた方がよりセキュアな運用ができます。

ちなみに、そのような構成にしても中間CAにはKeyUsege側に署名可能(keyCertSign)としてあるので、他の目的の署名もできますが、EKU検証チェーンの中で使用目的と一致せずその証明書は無効となる仕組みです。

中間CAを使うと構造によってはRoot CAの失効リストも運用する必要がでてきますので、その場合は管理の手間が増えます。

## X.509 v3
ここまで**v3拡張署名用セクションX.509**等の記述がありましたが、これは**X.509 v3**という証明書形式の拡張部分を差していました。X.509形式の証明書にはバージョンがあり、これが3(現行)だと拡張領域を使うことができます。

ここには主に次のようなものを指定できます。

| v3拡張                     | 意味               | 主な用途         |
| ------------------------ | ---------------- | ------------ |
| `basicConstraints`       | CAか末端証明書か        | CA権限の制御      |
| `keyUsage`               | 鍵を何の暗号処理に使えるか    | 署名・CA署名など    |
| `extendedKeyUsage`       | 証明書を何の用途に使えるか    | TLS、コード署名など  |
| `subjectKeyIdentifier`   | この証明書の公開鍵の識別子    | CA/鍵の識別      |
| `authorityKeyIdentifier` | 署名したCA鍵の識別子      | 証明書チェーン構築    |
| `subjectAltName`         | Subjectの追加識別名    | DNS名、IP、メール等 |
| `crlDistributionPoints`  | CRLの取得場所         | 失効確認         |


### 補足説明

#### critical

**critical**に指定した項目を理解できなけば、証明書自体を無効にするという指定です。ただし検証側がv3以前の場合はもともと拡張領域を理解できないので、この指定は意味を持ちませんが、そのような場合でも本体側のversionフィールドの部分で、想定外のバージョンというエラーになる可能性はあります。

また理解したら従う必要があり、`basicConstraints`,`keyUsage`,`extendedKeyUsage`などに指定しておきます。

criticalは最初の項目である必要があり、そのあと`,`をつけて実際の指定値を置きます。


#### subjectKeyIdentifier
`subjectKeyIdentifier`の値は多くの場合`hash`となっていますがこの場合は自動生成されます。hashなので同じ証明書なら常に同じ値になります。あまりみかけませんが値を指定することもできます。

この値は証明書チェーンを検証する時に使われ、末端の証明書の`authorityKeyIdentifier`の値と、CA証明書の`subjectKeyIdentifier`と照らし合わせることで結び付けられます。 

ただし、バージョン3以前は`Issuer`と`Subject`で検証されますので、なければ証明書チェーンが検証できないというわけではありません。逆に存在していて、それらと不整合が起きた場合にその証明書チェーンを有効とするかどうかは実装に依存します。

#### authorityKeyIdentifier
`authorityKeyIdentifier`の値は、keyid,issuer とすることで、証明書発行者のKeyIDが取得できれば、その値、そうでない場合はissuer（通常はそれに発行連番:issuerがその上部の発行者から受け取った連番)で区別されます。keyid:alwaysとするとkeyidが取得できなければ発行エラーとなります。

ちなみに`issuer,keyid`としても優先順位は変わらずkeyidとなります。どちらも出力させておきたい場合はそのふたつに:alwaysを指定します。

どちらの場合でもチェーンを見つける手がかりであり、実際の証明書の値がおかしければ証明書チェーンは有効にはなりません。

次のように全体の整合性を保っておきます。

| 子 | 親 |
| :-: | :-: |
| Issuer | Subject |
| AKI  | SKI |
| 署名 | 親の証明書で検証 |


## 実践
ここからは、実際にCAを作ったり、署名要求に署名したりしていきます。

### CA の作成

#### ルートCA用のキーを作成します。

```
openssl genpkey \
  -algorithm RSA \
  -pkeyopt rsa_keygen_bits:4096 \
  -out root-ca.key
```

#### 署名要求を作成します

```
openssl req \
  -new \
  -key ca.key \
  -out ca.csr \
  -subj "/C=JP/O=Example/CN=Example CA"
```

#### 自身または親CAで署名します。

もしすでに公に有効なCAに署名をしてもらうなら ca.csrを渡します。プライベートCAの場合は、Root CAを作るなら自身の鍵、中間CAを作るなら親のCAの鍵で署名します。

`openssl req`では`-addext` パラメーターで拡張部分を指定できますが、`openssl x509`ではファイル指定する必要があります。
後述しますが、req=署名要求で指定した拡張署名部分は設定によっては、そのまま採用可能です。
ただ、通常のCAではセキュリティ的な観点から署名時に部分的に上書きされるか、すべて無視されるのが一般的です。

もし、プライベートなルートCAを持っていてそちらでも失効の管理をしたいなら x509で署名するのではなく、親のCAで`openssl ca`コマンドから署名して下さい。`openssl ca`コマンドにつきましてはこの後説明します。


```
openssl x509 \
  -req \
  -in ca.csr \ ※ 作成したCAの署名要求
  -signkey ca.key \ ※ 署名するCAの秘密鍵(自己署名なら自分の鍵)
  -days 7300 \
  -sha256 \
  -extfile ca.ext \
  -out ca.crt ※ 作成する証明書の出力先
```
```
# ca.ext
# 前例ではセクションがありましたが、使い分けが不要ならセクションは不要です
basicConstraints = critical, CA:true
keyUsage = critical, keyCertSign, cRLSign
subjectKeyIdentifier = hash

```

### CA用のopenssl.cnfの作成

CA用のディレクトリを作成し、CAの秘密鍵、証明書をそこへ移動させます。署名要求は再作成できますしこのあとは使わないので削除してもかまいません。

この後ディレクトリ構造にあわさせて、openssl.cnfを作成します。

前述の通り、相対パスにするか絶対パスにするかは好みですが、dirを定義していますので、絶対パスにしておいた方が間違いが少ないです。ディレクトリを動かしたらdirの値を変える運用にしましょう。

[設定ファイルサンプル](https://github.com/sugakenn/blog_box/blob/main/create_cert/openssl_sample_for_creater_cert.cnf)
```
# openssl_ca_sample.cnf 

[ ca ]
default_ca = CA_default

[ CA_default ]
dir               = [CAディレクトリ]
#certs            = $dir/certs # 発行した証明書の保存場所 自動保存されるわけではないので、不要
#crl_dir          = $dir/crl # 発行したcrlの保存場所　自動保存されるわけではないので、不要
new_certs_dir     = $dir/newcerts # 新規の証明書が保存される場所　自動保存　中身は消さずに保存
database          = $dir/index.txt　# 証明書の管理データベース
serial            = $dir/serial # 証明書管理番号が保存される
crlnumber         = $dir/crlnumber # 失効リストの管理番号が保存される

certificate       = $dir/ca.crt #CA証明書へのパス
private_key       = $dir/ca.key #CA秘密鍵へのパス

default_md        = sha256
default_days      = 825
default_crl_days  = 30 # CRLの有効期限　切れると利用者側でエラーになる事があるので注意

policy            = policy_loose # 署名ポリシーのセクションを指定　
unique_subject    = no # 同内容のsubjectの発行を制限するか

# x509_extensions = v3_sig # v3署名用のセクションを指定 引き数で指定するのでここでは指定しない

name_opt        = ca_default # DN(識別名)の表示形式 ca_defaultは内部で定義済みの名前です　
cert_opt        = ca_default # 証明書の表表示形式

# 署名要求時につけられたの拡張署名の取り扱い
# none 無視
# copy CA側の拡張設定があるものに関しては上書き
# copyall すべて署名要求の通りにコピー(運用注意)
copy_extensions = copy

[ policy_loose ]
countryName             = optional
stateOrProvinceName     = optional
localityName            = optional
organizationName        = optional
organizationalUnitName  = optional
commonName              = supplied
emailAddress            = optional


# ============================================================
# v3拡張署名用セクション
# ============================================================

[v3_server]
basicConstraints = critical, CA:false
keyUsage = critical, digitalSignature, keyEncipherment
extendedKeyUsage = serverAuth
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always,issuer

[v3_client]
basicConstraints = critical, CA:false
keyUsage = critical, digitalSignature
extendedKeyUsage = clientAuth
subjectKeyIdentifier = hash
authorityKeyIdentifier = keyid:always,issuer
```

### 署名

署名要求に対して署名をします。

```
openssl ca \
    -config "openssl設定ファイル" \
    -extensions "拡張署名セクション名" \
    -in "署名要求" \
    -out "証明書保存先"
```

これでCAの作成は終了です。

こうして署名をした場合は`new_serts_dir`や`database`に保存されるデータを使ってCRLを管理することができるようになります。

### 失効処理とCRL作成

失効リスト(CRL)を作ります。

まずは証明書を失効させます。

revokeに失効させたい証明書を指定します。`new_certs_dir`のデータを消してはいけないのはそのためです。また、指定した証明書は、発行履歴である`database`に該当の行が存在する必要があります。

```
openssl ca \
  -config openssl.cnf \
  -revoke new_certs_dir/client.crt \
  -crl_reason keyCompromise
```

`-crl_reason`は省略可能ですが、次の値を使って失効理由を指定します。

| 値                      | 意味        | 使う場面                 |
| ---------------------- | --------- | -------------------- |
| `unspecified`          | 理由未指定     | 特に理由を記録しない           |
| `keyCompromise`        | 秘密鍵の漏洩・侵害 | 秘密鍵が盗まれた、漏洩した可能性がある  |
| `CACompromise`         | CA秘密鍵の侵害  | CAの秘密鍵が漏洩した可能性がある    |
| `affiliationChanged`   | 所属変更      | 部署・組織・所属などが変わった      |
| `superseded`           | 証明書の置き換え  | 新しい証明書を発行し、古いものを廃止   |
| `cessationOfOperation` | 運用終了      | サーバー・サービス・利用者などの運用終了 |


失効リストを作成します。ここで作成したファイルを配布して組み込んでもらいます。

```
  openssl ca \
  -config openssl.cnf \
  -gencrl \
  -out crl.pem

```

先ほどの設定ファイル上の失効リストの期限は30日としていました`default_crl_days`。パラメーターからも期限は変更できますが、気を付けなければならないのは失効リストを使う設定を入れると、アプリによっては失効リスト不正で全体を起動できなくなることがあることです。それには有効期限切れも含まれたりします。


そのような場合は、新しい失効リストを定期的に提供しなければなりません。無期限にすることはできないので、稀にしか更新しないなら大きな値にしておくといいかもしれません。

この日数は`-crldays`オプションで作成時に任意に変更もできます。


### サンプルコード

サーバー証明書とクライアント証明書を作成するスクリプトを作ってみました。

PFXファイルはパスワードを付けて出力該当の端末に**エクスポート不可**でインストール後、削除する前提です。もし、PFXファイルやその中の秘密鍵が漏れた場合は、先ほどの失効リストへ加えます。

ここまで書いておいてなんですが、最後に重要な話があります。

**秘密鍵を配布する運用はよくありません。**クライアントが秘密鍵と署名要求を作ってそれをCAが署名するという、秘密鍵をまったく動かさない運用が正規の運用方法です。

```bash
#!/bin/bash
set -e

# ----------------------------------------
# 引数チェック
# ----------------------------------------
if [ "$#" -lt 2 ] || [ "$#" -gt 3 ]; then
    echo "Usage: $0 <openssl.cnf> <CommonName> [CA_CERT]"
    exit 1
fi

CONFIG="$1"
COMMON_NAME="$2"
CA_CERT="${3:-}"

# ----------------------------------------
# openssl.cnf の存在確認
# ----------------------------------------
if [ ! -f "$CONFIG" ]; then
    echo "Error: config file not found: $CONFIG"
    exit 1
fi

# CONFIGを絶対パスにする
CONFIG="$(realpath "$CONFIG")"

# openssl.cnf と同じディレクトリ
BASE_DIR="$(dirname "$CONFIG")"

# ----------------------------------------
# Root CA が指定された場合のチェック
# ----------------------------------------
if [ -n "$CA_CERT" ]; then
    if [ ! -f "$CA_CERT" ]; then
        echo "Error: Root CA certificate not found: $CA_CERT"
        exit 1
    fi

    CA_CERT="$(realpath "$CA_CERT")"
fi

# ----------------------------------------
# 出力ファイル
# ----------------------------------------
KEY="${BASE_DIR}/${COMMON_NAME}.key"
CSR="${BASE_DIR}/${COMMON_NAME}.csr"
CRT="${BASE_DIR}/${COMMON_NAME}.crt"
PFX="${BASE_DIR}/${COMMON_NAME}.pfx"

# ----------------------------------------
# 1. 秘密鍵作成
# ----------------------------------------
echo "=== Create private key ==="

openssl genpkey \
    -algorithm RSA \
    -pkeyopt rsa_keygen_bits:3072 \
    -out "$KEY"

chmod 600 "$KEY"

# ----------------------------------------
# 2. CSR作成
# CN と SAN は同じ値
# ----------------------------------------
echo "=== Create CSR ==="

openssl req \
    -new \
    -config "$CONFIG" \
    -key "$KEY" \
    -out "$CSR" \
    -subj "/CN=${COMMON_NAME}" \
    -addext "subjectAltName=DNS:${COMMON_NAME}"

# ----------------------------------------
# 3. CA署名
# openssl.cnf の [v3_sig] を使用
# ----------------------------------------
echo "=== Sign certificate ==="

openssl ca \
    -config "$CONFIG" \
    -extensions v3_sig \
    -in "$CSR" \
    -out "$CRT"

# ----------------------------------------
# 4. PFX作成
# CA_CERT指定時はPFXへ含める
# ----------------------------------------
echo "=== Create PFX ==="

if [ -n "$CA_CERT" ]; then

    openssl pkcs12 \
        -export \
        -inkey "$KEY" \
        -in "$CRT" \
        -certfile "$CA_CERT" \
        -out "$PFX"

else

    openssl pkcs12 \
        -export \
        -inkey "$KEY" \
        -in "$CRT" \
        -out "$PFX"

fi

# ----------------------------------------
# CSR削除
# ----------------------------------------
rm -f "$CSR"

echo
echo "Completed."
echo "Private key : $KEY"
echo "Certificate : $CRT"
echo "PFX         : $PFX"

if [ -n "$CA_CERT" ]; then
    echo "CA_CERT     : $CA_CERT"
fi
```
